# 合成 30T MoE 单 Agent 推理预测

2026 年基准情景为 **0.801 GPU·h/主 Agent 日**，采用 H100、FP8 权重、每天一个编码任务当量。2030 年基准为 **0.370 GPU·h/主 Agent 日**，假设 GB300、FP4 权重和每天 3.46 个任务当量。数值衡量服务该 Agent 所分摊的设备工作量。现实研究员每天的任务当量仍缺少直接观测。

## 参数依据

30T 为本次情景目标。沿用 40T 分支的 Kimi K2 风格结构，只调整路由专家总数。按下式选最接近目标的整数，保持 60 个 MoE 层、隐藏维度 7,168、专家中间维度 2,048 和非路由预算 B=10,058,752,000。

- 每新增一个路由专家在全部 MoE 层的专家矩阵参数 E=3×7,168×2,048×60=2,642,411,520，路由器参数 R=7,168×60=430,080。
- 专家数 n=round((30×10¹²−B)/(E+R))=11,348。总参数 B+n(E+R)=30,001,025,228,800，较目标高约 0.0034%。
- 每 Token 激活参数为 B+nR+K×E。Top-4、Top-8、Top-16 分别为 25.509B、36.079B、57.218B。FP8 每参数一字节、另计 3% 元数据时，权重常驻容量约 30.90 TB。

单任务输入、输出、缓存命中和峰值上下文采用原先 23 条计量完整的编码轨迹。三条路径按每题输出 Token 的 P10/P50/P90 选取整条记录，依次配 Top-4/8/16。其余年际工作量、硬件、精度与服务假设取自同一份审计。原始统计口径、外推限制和缺失数据见[证据台账](../agentic_40t_forecast/evidence.md)和[逐题来源](../agentic_40t_forecast/trace_sample.csv)。其中的 40T 结构与结果由本页的推导和复算取代。

## 结果

单位为 GPU·h/主 Agent 日。模型容量列给出基准路径中单副本按 TP×EP 分组向上取整的容量下界。样本范围固定基准配置，重放 23 条轨迹；服务压力范围同时改变缓存、解码 batch 与逐层通信延迟，取工程组合的最低 P10 和最高 P90。二者均为条件范围。

| 年 | 保守 | 基准 | 激进 | 基准较 40T | 基准副本卡数（40T → 30T） | 样本 P10–P90 | 服务压力范围 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2026 | 0.330 | 0.801 | 1.703 | −23.15% | 768 → 576 | 0.419–1.602 | 0.109–6.977 |
| 2027 | 0.284 | 0.804 | 2.066 | −0.01% | 384 → 384 | 0.427–1.607 | 0.112–7.035 |
| 2028 | 0.239 | 0.591 | 1.748 | −0.01% | 192 → 192 | 0.270–1.195 | 0.068–5.381 |
| 2030 | 0.239 | 0.370 | 1.368 | −45.86% | 144 → 72 | 0.216–0.726 | 0.068–3.942 |

2027、2028 的基准配置在两个模型下落入相同的部署分组；Top-8 激活参数只从 37.71B 降到 36.08B。2030 的基准副本从两个 72 卡组降到一个，等待 collective 的分摊设备时间随之减少。2026 年基准若将缓存命中降为零，预测增加 163%；将输出提高至样本 P90 增加 96%；逐层通信延迟从 10 µs 增至 20 µs 增加 92%。这些是合成部署估算，缺少目标引擎实测。
