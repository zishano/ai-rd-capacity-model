# 合成 30T MoE 单 Agent 推理预测

[新版第一层报告：会话分解、逐请求数据、三张研究图及可编辑 PPT](workload/README.md)。以下保留原版单路径预测，供复算与回归对照。

2030 年 11 月的基准需求为每天 **8.67 个编码任务当量、455.3 万输入 Token、6.53 万输出 Token**。输入量来自历史使用强度的线性外推，再按 GB300、FP4 权重和基准服务效率换算为 **0.926 GPU·h/主 Agent 日**。2026 年 11 月以每天一个基准任务归一化。

## 参数依据

30T 为本次情景目标。沿用 40T 分支的 Kimi K2 风格结构，只调整路由专家总数。按下式选最接近目标的整数，保持 60 个 MoE 层、隐藏维度 7,168、专家中间维度 2,048 和非路由预算 B=10,058,752,000。

- 每新增一个路由专家在全部 MoE 层的专家矩阵参数 E=3×7,168×2,048×60=2,642,411,520，路由器参数 R=7,168×60=430,080。
- 专家数 n=round((30×10¹²−B)/(E+R))=11,348。总参数 B+n(E+R)=30,001,025,228,800，较目标高约 0.0034%。
- 每 Token 激活参数为 B+nR+K×E。Top-4、Top-8、Top-16 分别为 25.509B、36.079B、57.218B。FP8 每参数一字节、另计 3% 元数据时，权重常驻容量约 30.90 TB。

单任务输入、输出、缓存命中和峰值上下文采用原先 23 条计量完整的编码轨迹。三条路径按每题输出 Token 的 P10/P50/P90 选取整条记录，依次配 Top-4/8/16。研究员历史使用量来自 OpenAI 的同口径日度图值，原始轨迹支持每题的输入/缓存/输出计数。硬件与服务效率沿用独立情景假设。[历史使用量、公式与假设](usage_method.md) · [逐题计量](../agentic_40t_forecast/trace_sample.csv) · [架构与服务证据台账](../agentic_40t_forecast/evidence.md)

## 两层预测结果

每年采用 11 月 18 日的需求水平。保守、基准、激进三档共用同一个历史需求倍率，分别代入各自的任务轨迹、Top-K 和年度硬件。样本 P10–P90 是在基准配置下替换任务得到的 GPU·h 分位数。压力范围另计服务条件变化。

|年|日任务当量|保守 GPU·h/日|基准 GPU·h/日|激进 GPU·h/日|基准任务样本 P10–P90|服务压力范围|
|---|---:|---:|---:|---:|---:|---:|
|2026|1.00|0.330|0.801|1.703|0.419–1.602|0.109–6.977|
|2027|2.92|0.644|1.564|3.333|0.830–3.125|0.218–13.684|
|2028|4.84|0.714|1.246|2.625|0.569–2.520|0.144–11.350|
|2030|8.67|0.957|0.926|2.006|0.542–1.818|0.171–9.868|

2030 基准轨迹每题含 525,067 个输入 Token、495,872 个缓存输入 Token 和 7,535 个输出 Token。乘以 8.67144 得每日约 4,553,087 个输入，其中 4,299,924 个命中缓存，253,163 个需预填充，另生成 65,339 个输出 Token。按所设共享服务条件每题约 0.10677 GPU·h，全年表值表达当年 11 月的日速率。2030 保守路径使用 B200、基准路径使用 GB300；前者虽然每题输出更短，但服务配置不同，三档结果无需按数值递增。
