# 合成 40T MoE · 一名研究员的一个主 Agent

**基准预测为 2026 年 1.04 GPU·h/归一日，2030 年 0.68。** 2026 的计量单位为每天处理一个公开代码修复任务当量，2030 基准为 3.46 个当量。研究员真实每天交给这个 Agent 的任务量未知。基准 2026 使用 H100、FP8 权重；基准 2030 假设 GB300、FP4 权重、更高服务效率。这样的设备与精度变化足以抵消情景中的工作量增长。

## 哪些因素最影响 GPU·h

2026 基准的 1.04 GPU·h 中，prefill 约 0.077、decode 约 0.965。在 3% 权重元数据、10% 运行时预留和 TP×EP 取整下，单副本需要至少 768 张 H100；此处的 1.04 是分摊设备工作量。若独占该副本全天，预留量为 18,432 GPU·h，与任务工作量是两种采购口径。

|一次只改一项，其他采用 2026 基准|GPU·h/日相对变化|解释|
|---|---:|---|
|将基准轨迹 94.4% 的缓存命中降为零|+125%|重复输入几乎全部重新预填充|
|日任务量翻倍|+100%|固定服务条件下各任务的设备工作量相加|
|每题输出从 7,535 提高至样本 P90 的 15,558|+99%|逐 Token 解码通信轮次增加|
|逐 MoE 层 collective 从 10 提至 20 µs|+97%|在当前瓶颈下，解码等待计入整个副本的设备时间|
|解码 batch 从 1 改为 4|−69%|理想同批共享减少分摊轮次，调度空泡会削弱此效果|

## 复算

在仓库根目录运行。日常复算只需 Python 标准库和随附 CSV，显式加载 40T 配置。第二个命令单独联网验证抽样顺序和全部原始用量字段。

```bash
python3 -B analysis/agentic_40t_forecast/forecast.py --output /tmp/agentic_40t_forecast
python3 -B analysis/agentic_40t_forecast/verify_traces.py
```
