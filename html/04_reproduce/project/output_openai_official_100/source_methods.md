# OpenAI公开数据的方法与可推导边界

重新下载日期：**2026年11月21日（Asia/Shanghai）**。本次依据OpenAI官方[11月18日报告](https://openai.com/index/research-acceleration-jagged-frontier/)与[9月6日报告](https://openai.com/index/research-acceleration-view-inside-openai/)的网页内嵌图表及方法说明。公开图值是经过抽样、截尾或平滑的统计量，不是逐任务、逐请求原始日志。

**累计Agent工作日。** 11月报告将符合条件的Agent时长加总，8小时计一个工作日；研究组织每名员工的自然日作为人群分母，图为28日后向均值。父Agent、子Agent分别计时，并包含自动评审；排除codex exec等程序化流量。时长由连接事件和客户端遥测估计，同一turn中超过30分钟的事件间隙不计。这是筛选后的墙钟时间，不是GPU执行时间。乘8可得累计小时，除以24可得平均在线活动当量，不能识别会话启动数。

**研发任务发起率。** 11月报告抽样上下文窗口并识别其中开始的任务，排除标注/评分、无匹配研发类别及自动请求。每个账户日发起数按至少有一项任务者的P95截尾，再除当日窗口抽样率和有效研究人员名册人数；报告28日均值，排除公司休假期。7月使用的名册有所不同。该指标是处理后的发起率，不是成功完成数或每次模型调用数。

**18类输出Token。** 9月[分类输出图](https://openai.com/index/research-acceleration-view-inside-openai/#chart-4QLdZ4iw0n4L9rYGTvteZK)抽样2%的在职研究员工内部编码会话，放大估计Token量。按非零抽样用户的日输出P95截尾，超阈值者各类别同比例缩减；排除标注/评分及无匹配类别，采用14日后向均值，单位为每研究员工每日输出Token。图值不代表完整使用量。同文另一张部门相对增长图采用ChatGPT与Codex合计、员工中位数及28日等效量，并明确包含隐藏推理Token；18类图的独立方法未重申这一点。本次沿用“官方输出Token”名称，不把另一图的中位数、窗口或推理Token定义直接移用。

**窗口与人群不能完全对齐。** 形式上可取相邻两个14日均值的平均构造28日平滑值，但这不能消除输出与任务率之间的休假剔除、抽样单位、截尾对象和人员名册差异。同日输出除以发起率只是汇总强度，不能识别单个任务的账单或成本。

**并发分布。** 11月仅保留当日发过公开Slack消息或提交过代码的研究员日。日峰要求至少30秒持续重叠，父子分别计；先对每人最近28个有效日期的日峰求均值，再分九档、个人等权。6月28日至7月4日缺数，7月9–16日改用客户端计时。它不是全团队同时峰值；9月“过去7天曾达四并发者占比”也不能与其直接拼接。

**预测与未知项。** 百人外推需明确人均使用强度相同。公开聚合量无法唯一识别A更多会话、B更长任务、C两者及构成共同变化，不再为三机制强行赋值。本次采用保持末值、线性、斜率逐年衰减三种趋势情景，名称与上述机制区分。Input、缓存账单、调用次数、请求上下文、LLM峰值及KV驻留未被这些图识别；仅凭官方输出Token不能补齐它们或完整推理FLOPs。
